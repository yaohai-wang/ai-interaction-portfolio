## 视频实际展示与 Agent 框架取舍

只采用视频可见部分：

1. **发起与上下文**：饮食档案、目标、场景、餐次、偏好标签；自然语言输入后的可核对条件。
2. **建议呈现**：菜品列表、食材/做法/营养详情，进入今日计划。
3. **人在环**：修改份量、取消、移出/撤销、确认实际吃了。
4. **结果交付**：计划和已吃分别计数，确认后跨模块更新。
5. **依据与边界**：趋势说明披露示例模型与不确定性。

视频中没有可证明的 Agent 工具调用日志、执行计划、真实网络检索或自主执行链，相关章节不要硬补。保存失败、无结果、推荐失败等状态虽有代码（`README.md:238–240`），本次候选80秒视频未呈现，不声称视频覆盖它们。

## 可用的设计取舍（代码归纳，文案仍待 Kai 确认）

- 「建议与记录分开」：加入计划不代表已经吃了。确认餐次与实际份量之后才更新已吃，避免语义混淆和重复统计。证据 Q11–Q13。
- 「让上下文可见、可改」：目标、过敏、忌口和已识别条件在推荐面板呈现。证据 Q08–Q10。不能声称经用户研究验证。
- 「反馈回应行动，不评价身体」：伙伴回应记录与习惯动作；负向情绪只由用户主动选择短暂触发。证据 Q16。不能声称健康效果。
- 「不确定性进入界面」：区分实测与情景估算，披露占位模型；长期范围不输出数字。证据 Q15。不是医学模型验证结果。
